# SVG 配图规范

## 图的任务

图应让读者看见正文难以直接说明的关系。画之前先写出它要回答的一个问题，再选择图形：

| 要解释的问题 | 适合的图形 |
| --- | --- |
| 数据存哪些字段，怎样排列 | 字段横条、记录框、索引与引用关系 |
| 哪个程序包含哪些组件，在哪里运行 | 带边界的部署图或组成图 |
| 谁先调用谁，返回了什么 | 有参与方和时间顺序的时序图 |
| 记录如何被消费或状态怎样改变 | 带实例数据的状态图、队列或步骤图 |
| 失败后从哪里恢复 | 原记录与恢复操作的对应图 |
| 两种方式的差别在哪里 | 相同对象、相同比例和标注规则的并列图 |

复杂内容可以拆成总体结构与局部机制两张图。一张图不要同时承担全篇目录、执行过程和最终结论。

## 视觉语言

采用早期 LevelDB 图和本项目已认可改稿的共同样式：白底、细黑线、直接的矩形、字段分隔线和箭头。保持 SVG 可编辑。

建议起点如下，可根据内容调整，不能为了符合尺寸而缩小到难以阅读：

| 项目 | 起点 |
| --- | --- |
| 画布 | `viewBox`，常用宽度 1000，高度随内容；简单图可以更窄 |
| 背景 | `#ffffff`，保持浅色图在深色主题中也可读 |
| 边线与箭头 | 黑色，约 1.6 px，统一箭头头部 |
| 字体 | `Arial, Helvetica, PingFang SC, Microsoft YaHei, sans-serif` |
| 节点正文 | 约 22 px；少量字段和标注可用 18–20 px |
| 局部对象标题 | 约 22 px，字重 600；正文普通字重 |
| 留白 | 框内文字四周留余量；连线在框外布置，标签与线错开 |

1000 宽的图进入博客后会缩到正文宽度，必须按实际显示效果检查。若必须不断缩字号，优先减少图中内容或拆图。

颜色只在有含义时使用，通常白底加一两种强调色就够。可复用的填充与边线：

| 用途示例 | 填充 | 边线 |
| --- | --- | --- |
| 当前执行者或重点对象 | `#b0e3e6` | `#0e8088` |
| 有效、新增或已确认的数据 | `#d5e8d4` | `#82b366` |
| 旧记录、已覆盖或非活动对象 | `#f5f5f5` | `#666666` |
| 丢失、拒绝或需要注意的状态 | `#f8cecc` | `#b85450` |
| 需要额外区分的一组对象 | `#b1ddf0` | `#10739e` |
| 需要额外区分的另一组对象 | `#d0cee2` | `#56517e` |

颜色含义以当前图为准；复杂图补图例，简单图直接写状态。不要只靠颜色表达差异。

不用渐变、阴影、大圆角卡片、装饰图标、巨大标题、编号徽章或结论横幅。颜色和排版服务于结构，不把技术图画成宣传海报。

## 标注和连线

- 图内写对象、字段、参数、操作和必要状态；完整解释放到图后的段落。
- 图名和“图 N”放在 Hugo caption 中。局部的 `Message`、`Checkpoint` 等对象名称可以放在图内。
- 箭头起止于真正的发起方和接收方。服务发现可以返回目标地址，不应被画成发送业务消息的主体。
- 实线、虚线和双向箭头的含义保持一致。时序图常用实线表示请求、虚线表示返回；部署图则按实际调用或数据方向标注。
- 将箭头与标签、节点标题、组边界分开摆放。文字边界检查通过，也可能仍有线条穿字，必须实际查看。
- 相同对象沿用正文中的编号。例如首次保存 `op-42`，后续查询仍用 `op-42`；不能在响应丢失后假定调用方已经取得只存在于响应中的编号。
- 字段和表结构为示意时在图注说明；进度条的长度不是实测耗时时也要说明。
- XML 中转义 `&`、`<` 等字符。提供 `xmlns`、`viewBox` 和有意义的 `<title>`；复杂图可增加 `<desc>`。避免依赖外链字体和 `foreignObject` 排版。

## 验收

先解析 SVG XML，确认文件有效；再用浏览器渲染，检查越界、重叠、缺字、线条穿字、方向和对齐。自动几何检查不能代替关系与视觉检查。

最后在原生文章中查看：正文宽度下的字号是否足够，图注是否接上前后段落，手机页面是否横向溢出，点击图片能否放大。只看单张 SVG 或构建成功，不能确认文章中的阅读效果。
